# Mooz for Windows

Trackpad pinch-to-zoom for any mouse, on Windows 10 and 11. Hold a modifier
(default **Shift**) and move the mouse up or down, or scroll, and the app under
the cursor zooms. Mooz lives in the notification area (tray). Left-click the
icon for Settings, right-click for the menu (Enabled, Settings, Quit).

This is a separate implementation from the macOS app, written in Rust. It
keeps the same gesture rules, defaults and settings.

## Build

From macOS or Linux (cross-compile):

```bash
cargo install cargo-xwin            # once
brew install llvm lld               # once, on macOS (clang-cl, lld-link, llvm-rc)
windows/scripts/build.sh            # tests, builds, packages dist/Mooz-<VERSION>-windows-x64.zip
```

`cargo-xwin` downloads the MSVC CRT and Windows SDK on first use, which means
accepting Microsoft's license for them.

On Windows: `cargo build --release` in `windows/` gives `target\release\Mooz.exe`.
CI (`.github/workflows/windows.yml`) builds, lints and tests on a Windows runner
and uploads the zip as an artifact.

Run `cargo test` anywhere to test the core. `cargo run` on macOS/Linux opens
the Settings window as a preview, using a config under `~/.config/mooz-windows-preview`.

The version comes from the repo-root `VERSION` file (via `build.rs`), the same
source as the macOS app. The exe gets the icon, version info and a manifest
(per-monitor DPI v2, `asInvoker`). The C runtime is linked statically, so no
Visual C++ redistributable is needed.

## How it works

| macOS | Windows |
| --- | --- |
| CGEventTap on the session | `WH_MOUSE_LL` hook on a dedicated thread with its own message loop |
| Cursor pinned by warping back every frame | Swallowing `WM_MOUSEMOVE` in the hook keeps the cursor still; the movement is `pt - anchor` |
| Synthesized IOHID magnify gesture | Two-finger pinch on a gesture-only virtual precision touchpad (`CreateSyntheticPointerDevice2`, Windows 11), or on the touchscreen around the cursor (`InjectTouchInput`, Windows 10); Ctrl + wheel via `SendInput` as the last fallback |
| HID modifier state for the watchdog | `GetAsyncKeyState`, overruled by a `WH_KEYBOARD_LL` physical-state tracker |
| Frontmost app bundle ID | Foreground window's exe name (`EVENT_SYSTEM_FOREGROUND`) |
| UserDefaults, read live | `%APPDATA%\Mooz\config.json`, reloaded when its mtime changes |
| Menu bar extra + SwiftUI Settings | Tray icon + egui Settings window (`Mooz.exe --settings`, its own process) |
| Accessibility permission | Not needed |

Layout:

- `src/core/`: no OS calls, unit tested on any platform. `gesture.rs` is the
  state machine ported from `GestureInterceptor.swift` (0.35 smoothing,
  0.01 per pixel, 0.15 per-event clamp, 0.2 s stall watchdog, subset modifier
  match). `wheel.rs` turns magnification into wheel deltas. Also `config.rs`,
  `modifiers.rs`, `applist.rs`.
- `src/win/`: the Win32 shell. `hook.rs` (input thread), `emit.rs` (SendInput),
  `tray.rs`, `apps.rs`, `autostart.rs`, `icon.rs`.
- `src/settings_ui.rs`: the Settings window (General, Applications, About).
- `assets/`: generated by `scripts/make-icons.sh` from `design/icon/`.

### Design decisions

- **A virtual touchpad pinch, like the mac's synthesized magnify.** Windows 11
  can host a synthetic precision touchpad (`CreateSyntheticPointerDevice2`
  with `PT_TOUCHPAD`, documented in Microsoft's Precision Touchpad
  Programming Guide). Mooz creates one with `SDCO_TOUCHPAD_GESTURE_ONLY`, so
  its input can only become gestures, never cursor motion or clicks, and puts
  two fingers on it symmetric about the center; each magnification step scales
  their distance by `1 + m` (`core/pinch.rs`). Windows recognizes a touchpad
  pinch at the mouse location: Direct Manipulation apps (Chrome, Edge, and
  Firefox since 2020) zoom smoothly at the cursor, other apps get the same
  fallback a real touchpad produces. Ctrl + wheel can't do this: Chromium
  never marks `WM_MOUSEWHEEL` as precise, so it only ever does its step page
  zoom. Frames are paced at ~120 Hz with keep-alives while the fingers are
  down; when they'd leave the pad they lift and re-grip.
- **A touchscreen pinch where there's no virtual touchpad.** On Windows 10
  and older Windows 11 builds the same two fingers go on the touchscreen
  (`InjectTouchInput`, no visual feedback), placed on screen around the
  cursor, 120 px apart at the start and at most 384 px. Browsers treat it as
  a touch pinch: the same smooth zoom at the cursor. Apps without touch
  support get Windows' legacy translation of the zoom gesture (Ctrl + wheel).
  The fingers' center is moved inward near a monitor edge so both stay on
  screen, and the cursor is put back where it was when they lift. A
  touchscreen from `CreateSyntheticPointerDevice` (`PT_TOUCH`) looks like
  the obvious choice, but with several monitors its contacts land far from
  the requested pixels (on the taskbar, in testing); touch injection maps
  them exactly on every monitor, negative coordinates included. If neither
  pinch works, or an injection fails, Mooz uses Ctrl + wheel.
- **Ctrl + wheel fallback, Steps by default.** Many apps zoom one level per wheel message no matter
  the delta, and Chromium counts whole wheel ticks (`HandleWheelEvent` in
  `web_contents_impl.cc`). So the default sends whole notches (120), at most
  one every 35 ms. "Smooth" sends fine-grained deltas for apps that honor the
  size; in Chrome and Edge it ends up the same as Steps.
- **Ctrl + wheel: apps see Ctrl alone.** Firefox picks its wheel action from the exact
  modifier set (`WheelPrefs::GetIndexFor` in `EventStateManager.cpp`), so
  Ctrl + Shift + wheel scrolls there, and many native apps test
  `wParam == MK_CONTROL`. Each tick is one SendInput batch: tap an unassigned
  "mask" key (0xE8), lift held Shift/Alt/Win, press Ctrl (unless held), send
  the wheel, release Ctrl, re-press the lifted keys, tap the mask key again.
  The mask taps keep Alt from focusing the menu bar, Win from opening Start,
  and Shift presses from counting toward Sticky Keys; pressing Ctrl only
  after Shift is up keeps a Ctrl + Shift layout-switch hotkey from firing. A
  low-level keyboard hook tracks physical key state and is authoritative
  over the OS async state (like HID state on macOS): if the user let go in
  the instant before a batch landed, the re-pressed key no longer counts as
  held, the gesture ends, and the key is released.
  Injection runs on its own thread.
- **Own input is tagged** (`dwExtraInfo = "MOOZ"`), so the hook ignores only
  its own events, not all injected input (remote desktop keeps working).
- **Hook health.** Windows silently removes a low-level hook whose callback
  is slow. The callback only runs the engine and queues deltas; injection
  happens afterwards. If the cursor moves while the hook has heard nothing
  for a second, the hook is reinstalled.

## Known limits

- The touchpad pinch needs a Windows 11 build with
  `CreateSyntheticPointerDevice2` (Microsoft's docs still mark it
  pre-release); elsewhere Mooz uses the touchscreen pinch. For the touchpad
  pinch, Windows Settings, Bluetooth & devices, Touchpad, **Pinch to zoom**
  must be on.
- The touchscreen pinch goes to the window under the cursor, and to apps
  that handle touch it is a real touch: one that uses touch to drag or
  select can do that instead of zooming. Pick Ctrl + Wheel in Settings for
  those.

- Keyboard state belongs to the active window, so the zoom lands in the
  active window. With "scroll inactive windows" on, pointing at a different
  window than the active one can scroll it instead of zooming.
- Apps running as administrator can't receive input from a normal process,
  so Mooz can't zoom them unless Mooz also runs as administrator.
- The app list matches the foreground window. UWP apps hosted in
  `ApplicationFrameHost.exe` all share that exe name.
- Shift + click-drag (range selection) zooms while Shift is the trigger, the
  same trade-off as on macOS. Pick another trigger key if that gets in the way.
- The exe is unsigned, so SmartScreen will warn on first launch.
- The Settings window needs OpenGL 2+. If it can't open (some VMs), Mooz shows
  the settings file path to edit instead.

## Debugging

Settings, About, **Debug log** (or `"debug": true` in config.json) writes
`%TEMP%\mooz-debug.log`: config, hook installs, whether the virtual touchpad
was created (or touch injection is used instead), where each touchscreen
pinch lands and which app is under it, foreground app, each gesture's begin/end with the modifiers seen,
moves swallowed and any cursor drift that had to be corrected, pinch frames
and re-grips, injection errors, and every Ctrl + wheel tick.

## Status

Lightly tested on Windows 11. The hook, tray, Settings window and the
Ctrl + wheel path ran and zoomed. The virtual touchpad pinch (now the
default) and cursor pinning are not confirmed yet; the debug log records both.
On Windows 10 (22H2, three monitors) the touchscreen pinch zoomed Chrome
smoothly at the cursor.

## Installer and updates

Use **Mooz-win-Setup.exe** from a Windows release for a per-user installation,
Start menu entry, uninstall support, and in-app updates. Open **Settings > Updates**
to check, download, and restart. Background checks are enabled by default and can
be disabled; downloads and restarts always need your click. Bare copies of
Mooz.exe cannot update in place.

Windows PR builds include an unsigned test installer and update packages as CI
artifacts. Trusted signing credentials must be configured before a public release.
See [RELEASING.md](RELEASING.md) for packaging, signing, the GitHub update feed,
release publication, and the install/upgrade/uninstall smoke test.

### Essentials settings

The settings window keeps mouse zoom, shortcut editing, input source and sensitivity in one flat view. Expand **Behavior & startup** for anchoring, zoom method, wheel style and Windows startup. Changes save immediately.

**Edit shortcuts** records one or more alternative hold-to-zoom combinations. Click **Add shortcut** (or an existing shortcut), release any keys already held, then press and release the new combination. Modifier-only shortcuts are supported; a combination may also include one ordinary key. Escape, Tab, changing tabs or leaving the window cancels recording. Duplicates are rejected and the final shortcut cannot be removed. Existing `modifiers` configs continue to work; new `shortcuts` entries persist separately and the gesture engine accepts any configured combination. Mooz does not intercept gestures inside its own settings window.

Windows CI captures the actual native settings renderer in the `Mooz-settings-windows` artifact, alongside the unsigned installer artifact. The installer upgrade smoke test preserves recorded shortcuts as well as sensitivity and startup registration.
